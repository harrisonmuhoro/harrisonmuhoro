A web-based attachment and internship management portal covering applicant records, departmental reviews, HR approvals, and placement administration.

**Key capabilities documented:**
- Student and applicant management
- Department supervisor workflows

- Four-role access model with departmental data isolation
- Document management and application tracking
- Administrative audit trails and dashboard reporting

**Technology:** PHP · MySQL · JavaScript

### 5. [Loan Management System](https://github.com/harrisonmuhoro/loan-system)

A PHP/MySQL loan management application with staff and loanee portals, repayment workflows, accounting controls, and a detailed legacy-debt management model.

**Key capabilities documented:**
- Loan application, review, approval, and repayment
- Admin, accountant, cashier, and loanee roles
- Legacy debt import, validation, and reconciliation
- Controlled migration from legacy debt to normal loans
- Immutable financial ledger and audit history
- Maker-checker approvals, CSRF protection, and server-side permissions

**Technology:** PHP · MySQL · JavaScript · PDO

### 6. [LifePilot Mobile](https://github.com/harrisonmuhoro/lifepilot-mobile)

An Android-first personal productivity and financial management application designed around offline-first usage and a modular mobile architecture.

**Current foundation:**

- TypeScript-based feature architecture

- Secure credential storage
- Planner and personal finance foundations
- Synchronization outbox foundation
- Automated checks and GitHub Actions CI

**Important:** The background synchronization engine and later planner, finance, and analytics phases remain on the development roadmap.

**Technology:** React Native · Expo · TypeScript · SQLite

## Engineering Principles

- **Build for the real world:** Design systems around the conditions and workflows in which people actually use them.
- **Security from the beginning:** Treat authentication, authorization, validation, auditability, and data protection as core engineering requirements.
- **Keep complexity intentional:** Prefer modular, understandable architecture that is justified by real requirements.
- **Design for change:** Make evolving business requirements safer and less expensive to implement.
- **Solve the workflow, not just the interface:** Focus on the operational problem behind the screen.
